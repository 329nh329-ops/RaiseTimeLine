# 技術スタック

## 1. フロントエンド

| 項目 | 内容 | バージョン |
|---|---|---|
| 言語 | TypeScript | 6.0系 |
| フレームワーク | React | 19.2系 |
| ビルドツール | Vite | 8.2系 |
| スタイリング | Tailwind CSS | 4.3系 |
| 実行環境 | Node.js | 26系 |
| 選定理由 | コンポーネント指向のモダンなフロントエンド開発が可能で、型による安全性を確保できるため |  |

## 2. バックエンド

| 項目 | 内容 | バージョン |
|---|---|---|
| 言語 | Java | 21（LTS） |
| フレームワーク | Spring Boot | 4.1系 |
| ビルドツール | Gradle | 9.7系（Gradle Wrapper） |
| DBアクセス方式 | Spring Data JPA（Hibernate） | Spring Bootに準拠 |
| 認証 | Spring Security＋自前のメール/パスワード認証（JWTによるステートレス認証） | Spring Bootに準拠 |
| 選定理由 | 実務での採用実績が豊富で、保守性・拡張性に優れるJava／Spring Bootの構成であるため |  |

## 3. データベース

| 項目 | 内容 | バージョン |
|---|---|---|
| 製品 | PostgreSQL | 18系（Dockerイメージ `postgres:18`） |
| 選定理由 | オープンソースで信頼性が高く、AWS RDS等のマネージドサービスでの運用実績も豊富なため |  |

## 4. 画像ストレージ

| 項目 | 内容 |
|---|---|
| サービス | AWS S3 |
| 用途 | 投稿添付画像・プロフィールアイコン画像の保存 |
| アクセス方式 | バックエンド（Spring Boot）がAWS SDKを介してアップロード・URL発行を行う。署名付きURLの利用有無は実装時に検討する |

## 5. 検索機能について
- 今回のスコープ（投稿本文の部分一致検索、ユーザー名の部分一致検索）はPostgreSQLの`LIKE`検索（またはpg_trgm等の拡張）で実現する想定とし、Elasticsearch等の専用検索エンジンは導入しない
- データ量・要求性能が増した場合は将来的な検討事項とする

## 6. コード品質チェック

| 項目 | 内容 |
|---|---|
| フロントエンド | [oxlint](https://oxc.rs/docs/guide/usage/linter.html)（`.oxlintrc.json`）でReact特有のルール（Hooksのルール違反等）を検出する。`npm run lint`で実行 |
| バックエンド | [Checkstyle](https://checkstyle.org/)（`backend/config/checkstyle/checkstyle.xml`）で未使用import・空catchブロック・文字列の`==`比較等を検出する。`./gradlew checkstyleMain`で実行、`./gradlew check`にも組み込む |

## 7. バージョン管理の方針
- フロントエンド（`frontend/package.json`）、バックエンド（`backend/build.gradle`）、データベース（`docker-compose.yml`）が実際のバージョンの一次情報であり、本表はそれに合わせて更新する
