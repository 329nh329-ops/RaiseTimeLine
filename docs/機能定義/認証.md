# 機能定義：認証

[機能一覧.md](../機能一覧.md) のNo.1に対応する詳細定義。

## 1. 概要
メールアドレスとパスワードによる、自前実装のユーザー登録・ログイン・ログアウト機能。外部認証ライブラリ・IdP（Google/X連携等）は使用しない。

## 2. 対象とする操作
- サインアップ（新規ユーザー登録）
- ログイン
- ログアウト

## 3. 入力項目

### 3.1 サインアップ
| 項目 | 必須/任意 | 型・制約 | 備考 |
|---|---|---|---|
| メールアドレス | 必須 | 文字列、メール形式、重複不可 | ログインIDとして使用する |
| パスワード | 必須 | 文字列、8文字以上、英字・数字をそれぞれ1文字以上含む | ハッシュ化して保存する |
| ユーザー名 | 必須 | 文字列、1〜30文字程度、前後の空白・制御文字は不可 | 表示名。重複は許容する（表示名であり一意キーではない） |

### 3.2 ログイン
| 項目 | 必須/任意 | 型・制約 | 備考 |
|---|---|---|---|
| メールアドレス | 必須 | メール形式 | |
| パスワード | 必須 | 文字列 | |

## 4. 処理仕様

### 4.1 サインアップ
- メールアドレスの重複チェックを行い、既に登録済みの場合はエラーメッセージ「このメールアドレスは既に登録されています」を表示する
- パスワードはハッシュ化（BCrypt）した上でデータベースに保存する。平文保存は行わない
- 登録成功後は自動的にログイン状態にはせず、ログイン画面に遷移する（登録とログインは別操作として扱う）

### 4.2 ログイン
- 入力されたメールアドレスに対応するユーザーが存在し、パスワードのハッシュが一致する場合にログインを許可する
- 一致しない場合は「メールアドレスまたはパスワードが正しくありません」というエラーメッセージを表示する（メールアドレスの存在有無を区別するメッセージにはしない）
- ログイン成功後、JWTアクセストークンとリフレッシュトークンを発行し、タイムライン画面に遷移する。フロントエンドはアクセストークンを保持し、以降のAPIリクエストのAuthorizationヘッダー（`Bearer <token>`）に付与する
- アクセストークンの有効期限は15分。リフレッシュトークンの有効期限は14日とする
- リフレッシュトークンはランダムな文字列として発行し、サーバー側ではハッシュ化して保存する（平文保存は行わない）
- アクセストークンの有効期限が切れた場合、フロントエンドはリフレッシュトークンを使って`POST /api/auth/refresh`を呼び出し、新しいアクセストークンを取得する。リフレッシュトークンは呼び出しの都度ローテーション（再発行・旧トークンの失効）する
- リフレッシュトークンが無効または期限切れの場合はログイン画面に遷移し、再ログインを求める

### 4.3 ログアウト
- `POST /api/auth/logout`でリフレッシュトークンを無効化し、ログイン状態を破棄してログイン画面に遷移する

### 4.4 認可
- 未ログイン状態でタイムライン・投稿・コメント・いいね・フォロー・プロフィール編集・検索等のAPIにアクセスした場合は拒否し、ログイン画面へ誘導する
- ログイン画面・サインアップ画面のみ、未ログインでもアクセスできる

## 5. バリデーション・エラー表示
- メールアドレス形式が不正な場合、「メールアドレスの形式が正しくありません」と表示する
- パスワードが8文字未満の場合、「パスワードは8文字以上で入力してください」と表示する
- パスワードが英字・数字の両方を含まない場合、「パスワードは英字と数字をそれぞれ1文字以上含めてください」と表示する
- ユーザー名が未入力の場合、「ユーザー名を入力してください」と表示する
- ユーザー名の前後に空白を含む場合、「ユーザー名の前後に空白を含めることはできません」と表示する

## 6. 対象外
- パスワード変更・再設定（パスワードリセット）
- 外部IdP連携（Google/X等でのログイン）
- 2段階認証
- ユーザーアカウント削除
