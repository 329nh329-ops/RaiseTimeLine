# RaiseTimeLine

X（Twitter）のようなタイムライン形式のテキストベースSNSアプリケーション。要件定義・設計・実装・テスト・デプロイという一連の開発プロセスを通じて、品質と保守性を担保しながら構築する学習用プロジェクト。

## 概要

タイムライン・フォロー・投稿・コメント・いいね・画像投稿・検索といったSNSの基本機能一式を備え、複数ユーザーが利用できるWebアプリケーションを提供する。インプレッション数の表示やリツイート機能は意図的に実装しない。

## 主な機能

| 機能 | 概要 |
|---|---|
| 認証 | サインアップ・ログイン・ログアウト（メールアドレス＋パスワード） |
| タイムライン | 全体タイムライン／フォロー中タイムラインの2タブ表示 |
| フォロー | 他ユーザーのフォロー／フォロー解除 |
| プロフィール | ユーザー情報・投稿一覧の表示、自分のプロフィール編集 |
| 投稿 | テキスト（＋画像）投稿の作成・編集・削除 |
| コメント | 投稿へのコメントの作成・編集・削除（第三者コメント可） |
| いいね | 投稿・コメントへのいいね（第三者いいね可、二重いいね不可） |
| 画像投稿 | 投稿への画像添付、AWS S3への保存 |
| 検索 | キーワード検索（投稿）・ユーザー検索 |

各機能の詳細は [docs/機能一覧.md](./docs/機能一覧.md) および [docs/機能定義/](./docs/機能定義/) 配下の各ドキュメントを参照。

対象外機能（ユーザーアカウント削除、パスワード変更・再設定、通知・メンション、リツイート・引用、インプレッション数表示、DM）は[要件定義.md](./要件定義.md)の3.2節を参照。

## アーキテクチャ

ブラウザで動作するフロントエンド（React）と、REST APIを提供するバックエンド（Spring Boot）、データを永続化するデータベース（PostgreSQL）で構成する。画像はAWS S3に保存する。ログイン（メールアドレス＋パスワード認証）が必須であり、未ログイン状態ではタイムライン等の主要機能を利用できない。

AWS上へのデプロイを想定する場合は、ALB（Application Load Balancer）を挟んだEC2 + RDS構成を前提として設計している。詳細は [docs/インフラ構成.md](./docs/インフラ構成.md) を参照（実際にデプロイするかは別途判断）。

## セットアップ

> 実装はこれから進めるため、以下は想定手順。実装の進行に合わせて更新する。

### 前提

- Docker
- Java 21（LTS）
- Node.js 26系

### 起動手順

```bash
# 1. PostgreSQLをDockerで起動
docker compose up -d

# 2. バックエンド（Spring Boot）を起動
cd backend
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
./gradlew bootRun

# 3. フロントエンド（Vite）を起動
cd frontend
npm install
npm run dev
```

フロントエンド起動後、`http://localhost:5173` にアクセスする。

### 品質チェック

```bash
# フロントエンド（lint）
cd frontend
npm run lint

# バックエンド（静的解析）
cd backend
./gradlew checkstyleMain
```

## 開発ルール

このプロジェクトはGit/GitHub運用ルールに従って開発する。Issue作成 → ブランチ作成（`feature/{Issue番号}-{短い説明}`） → 実装 → 品質チェック → Pull Request作成 → レビュー後マージ、という流れを徹底し、mainブランチへの直接pushは行わない。詳細は [CLAUDE.md](./CLAUDE.md) を参照。
